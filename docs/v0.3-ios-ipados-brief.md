# v0.3 — iOS / iPadOS port

> Status: **in progress** (commit en cours sur `main`).
> Initial brief, version maintained alongside the implementation.

## Goal

Ship the same MarkdownViewer experience on iOS and iPadOS, with as much shared code as possible. Target deployment: **iOS 16+** (matching the macOS 13+ floor).

## Strategy

A **second target** (`MarkdownViewerIOS`) is added next to the existing macOS one. Both targets share the entire `MarkdownViewer/Sources` folder; platform differences are gated by `#if os(macOS)` / `#if os(iOS)` rather than by file partitioning. This keeps the code surface tight and forces us to think about cross-platform shape on every change.

## Cross-platform compatibility audit

| File | Status | Notes |
|---|---|---|
| `MarkdownDocument.swift` | ✅ shared | `FileDocument`, `UTType` are Foundation/UTI — already cross-platform |
| `ViewMode.swift` | ✅ shared | enum + SF Symbols — both platforms |
| `FindBar.swift` | ✅ shared | pure SwiftUI ; the rogue `import AppKit` was removed |
| `MarkdownViewerApp.swift` | ✅ shared | `DocumentGroup`, `CommandGroup`, `Notification.Name` are SwiftUI/Foundation |
| `WebView.swift` | 🔧 dual impl | one `NSViewRepresentable` (macOS) + one `UIViewRepresentable` (iOS), both wrapping the same `WKWebView`. Shared coordinator handles all the JS bridge / file watcher / notifications. |
| `MarkdownEditor.swift` | 🔧 dual impl | `NSTextView` (macOS) vs `UITextView` (iOS) wrappers. The `Highlighter` (NSTextStorage attribute spans) is shared via a `Palette` enum that maps `NSColor`/`UIColor` semantic colors. |
| `ContentView.swift` | 🔧 mostly shared | iPhone hides the **Split** mode (no width for it) ; `HSplitView` (macOS-only) falls back to a plain `HStack { editor, divider, preview }` on iPad |
| `FileWatcher.swift` | ⚠️ macOS only | `DispatchSource.makeFileSystemObjectSource` works on iOS too, but iOS apps don't get a `representedURL` from `DocumentGroup` the same way — live reload from external editors is essentially a desktop concern. Wrapped in `#if os(macOS)` for now. |

## UX adaptations

- **iPad** — same 3-mode picker (Preview / Split / Source), `HStack` instead of `HSplitView`. Toolbar lives at the top.
- **iPhone** — Split mode is removed from the picker (`availableModes` filter on `UIDevice.current.userInterfaceIdiom == .phone`). Cycle (`Cmd+/` from a hardware keyboard) skips Split too.
- **Find** — keeps the floating SwiftUI `FindBar` ; on iOS the underlying call to `WKWebView.find(_:configuration:)` works identically.
- **Print** — `NSPrintInfo`/`printOperation(with:)` (macOS) maps to `UIPrintInteractionController` + `webView.viewPrintFormatter()` (iOS).
- **External links** — `NSWorkspace.shared.open(url)` on macOS, `UIApplication.shared.open(url)` on iOS.
- **Dark mode** — KVO on `NSApp.effectiveAppearance` (macOS) ; `webView.traitCollection.userInterfaceStyle` polled on render (iOS).

## Build configuration

- New `MarkdownViewerIOS` target in `project.yml`, `platform: iOS`, `IPHONEOS_DEPLOYMENT_TARGET: "16.0"`, `TARGETED_DEVICE_FAMILY: "1,2"` (iPhone + iPad).
- Dedicated `MarkdownViewer/Info-iOS.plist` with `UISupportsDocumentBrowser`, `LSSupportsOpeningDocumentsInPlace`, `UIFileSharingEnabled`, plus the same `UTImportedTypeDeclarations` and `CFBundleDocumentTypes` as macOS.
- Shared `Assets.xcassets` — `AppIcon.appiconset/Contents.json` now declares both the 10 macOS sizes and a single iOS marketing entry (`size: 1024x1024`, `idiom: universal`). The Xcode 14+ asset compiler synthesises the runtime sizes from the 1024 marketing icon.

## Open issues / risks

1. **iOS Simulator runtime missing on this machine.** `xcodebuild -showsdks` lists `iphonesimulator26.4`, but no runtime is installed yet. Triggered `xcodebuild -downloadPlatform iOS` in the background. Until the runtime lands, the iOS target is verified only at the project-generation level, not via `xcodebuild build`.
2. **Sandbox.** The macOS app is unsandboxed (personal use). iOS imposes the sandbox by design — once we want to access user files, we need security-scoped bookmarks (or to ride on `DocumentGroup`'s implicit handling, which works for documents the user picks themselves).
3. **`actool` thinning fix.** The post-compile script that calls `iconutil` only runs in the macOS target. It is iOS-irrelevant: iOS does not use `.icns` (it uses the asset catalog directly), so no equivalent post-compile is needed.
4. **`@SceneStorage` per-scene** behaviour differs slightly between macOS (one window = one scene) and iOS (a document scene can be backgrounded/restored). Should not affect us in practice but worth a runtime check.
5. **Hardware keyboard shortcuts** on iPad work via `keyboardShortcut(...)` SwiftUI modifiers — already present in our code.
6. **Live reload** is gated to macOS for now. Could be revisited later for iPadOS via `NSFilePresenter` if there's demand.
